SPRINT 01b - TIMER STARTS AFTER MOVEMENT
Project: Find The Cheeky Monkey (working title: Monkey Rush)
Engine: Unity 6000.3.6f1

GOAL
Start the level timer only when the monkey has finished moving, not at
GO. The player cannot tap before IsMovementComplete is true, so the
timer should not run during the walk.

DESIGN DECISIONS
- The timer shows the full time (1:00) after GO and while the monkey
  walks. It starts counting when CharacterPathMover.IsMovementComplete
  becomes true.
- LevelTimer watches the monkey in Update(). No new events and no
  changes to CharacterPathMover.
- IsMovementComplete cannot be stale: it is set to false in
  CharacterPathMover.Start() and again in StartGame(), and StartGame()
  has a hasStarted guard (confirmed by the developer).
- StopTimer() clears the watched monkey, so finding the monkey cancels
  a timer that has not started yet.

CHANGES
- Edited: Assets/Scripts/LevelTimer.cs
  New private field watchedMover. New public method
  StartTimerWhenMovementEnds(CharacterPathMover mover): resets the
  time, does not run yet, remembers the mover. Top of Update() starts
  the timer once the mover reports IsMovementComplete. StopTimer()
  clears watchedMover.
- Edited: Assets/Scripts/MapWindowController.cs
  One line (around 1668): levelTimer.StartTimer() replaced with
  levelTimer.StartTimerWhenMovementEnds(activePlayer).
- No scene, prefab, or CharacterPathMover changes. No Inspector steps.
